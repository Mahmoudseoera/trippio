# AI travel search

Compatibility fix: the page now loads a deferred classic `.js` bundle rather than browser modules. `node deliverables/build-travel-search.mjs` regenerates it from the shared core, UI module and authored HTML catalog; its catalog snapshot is a generated build output for direct-file use, not a manually maintained second catalog. Rebuild after catalog or module changes. HTTP still reads current catalog HTML. Mode switches visibly update the prompt/action and clear previous results while preserving the query. English number words (including the supplied Four days example) are parsed. The font path now points at an existing font.

Browser regression checks performed through the local Node server: Find Tours returns two original Giza products; Build My Trip recognizes Four days and renders four explicitly unbookable suggestion days for Sharm; Search by Image exposes its uploader and rejects submit without an image; no browser console errors appeared in these checks. Browser security disallows file:// navigation in the test tool, so direct-file execution was not visually verified. Live image recognition still needs Gemini credentials.

Open `ai-travel-search.html` using your current static web server, or run `node travel-search-server.mjs` (Node 22+) and visit http://127.0.0.1:8787/ai-travel-search.html.

The repository is static HTML/CSS/JS without a database, package manager, build system, backend, hosting manifest or established serverless deployment. The existing assistant's five `data-tour` records and `data-stop` entries in `ai-assistance.html` are adapted on demand. Other listing cards often link different products to the same generic details page; they are not treated as verified independently bookable records. No catalog copy or database was introduced. The new feature is isolated from the existing guide and booking scripts.

Find Tours: Gemini extracts intent server-side; deterministic matching filters explicit destinations and known durations and ranks listed attractions above text matches. If AI fails, Arabic/English keyword matching continues from the same source. Unknown durations, prices, age suitability and availability are labelled unverified. The fallback is a limited keyword interpreter, not full natural-language understanding.

Build My Trip: uses the same retrieval, places suitable authored day products once each in a proposed schedule, and marks remaining days as unbookable suggestions. Multi-day packages remain separate cards. Day count is required. No aggregate budget or confirmed availability is invented. Detailed ages, dates and qualitative budgets remain in the original request and need operator review; current catalog metadata cannot validate them. This version uses a deterministic proposed schedule after intent extraction rather than free-form model-authored itinerary prose.

Search by Image: JPEG/PNG/WebP up to 4 MB, preview, drag/drop, removal, server signature and size checks. Gemini receives image bytes only after submission; this application does not store or log them. Predictions are explicitly unconfirmed, including candidate names; users can confirm via text search. Unavailable image analysis never produces a fake identification. Provider data handling is governed by the configured Gemini account.

Configuration: set server-only `GEMINI_API_KEY` and `GEMINI_MODEL` in your process environment (template: `.env.travel-search.example`). The server does not automatically load env files. Choose a model available to your API account with vision and structured-output support. API credentials, quota and billing are separate from a consumer Gemini subscription. No live Gemini call was verified without credentials. Reference: https://ai.google.dev/api/generate-content .

Deployment: static hosting alone supports text fallback and deterministic plans. Run the Node service behind your same-origin HTTPS reverse proxy for Gemini modes; it binds localhost by default. Proxy `/api/travel-search` to it when retaining another static server. Server requests are limited to 12/minute/IP, with 25-second provider timeout and bounded JSON requests. Configure shared rate limiting and trusted proxy IP extraction before scaling beyond a single process; the included limiter uses socket addresses and does not trust forwarded headers. Secret/config/server files are excluded from public serving. Existing detail pages inside `AI Assistance/` have pre-existing relative asset links that assume root location; their forms are static previews, not live reservations. This feature links existing pages and makes no booking-completion claims.

Checks: `node deliverables/verify-travel-search.mjs`, `node --check` on new modules, `git diff --check`. No existing lint/type/build commands are present. Live Gemini vision/intent quality and browser visual QA require separate verification.
